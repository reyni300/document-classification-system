# Сервис разбора ДокАнализ — API и формат результата

Версия API: **v1**. Версия формата результата: **1.0** (`schema_version`).

## Зачем отдельный сервис

Разбор документа (OCR, модель, правила, поиск координат) вынесен в
самостоятельный сервис `parser_service`. Он не знает, кто и зачем его
вызывает: принимает файл, разбирает его в фоне и хранит результат под
**ID разбора**. Любой потребитель — веб-интерфейс, другая система,
консольный скрипт — получает результат по этому ID.

```
  HTML-страница ──файл──▶ POST /api/v1/parses ──▶ { "id": "…" }   (сразу)
                                    │
                                    ▼  очередь, обработка в фоне
                      OCR → модель → правила → координаты
                                    │
                                    ▼
                       data/parses/<id>/result.json
                                    ▲
  потребитель с ID ──▶ GET /api/v1/parses/<id> ──▶ статус; готово — результат
```

Веб-интерфейс (`web_client`) — один из потребителей. Он не импортирует ни
одного модуля разбора и общается с сервисом только через этот API.

## Жизненный цикл разбора

| Статус       | Что значит                                               |
|--------------|----------------------------------------------------------|
| `queued`     | файл принят и ждёт очереди (`queue_position` — номер)     |
| `processing` | документ распознаётся                                    |
| `done`       | готово, результат доступен                               |
| `failed`     | не удалось; причина в `error`, журнал шагов в `logs`     |

Документы обрабатываются строго по одному: при 5.6 ГБ памяти два разбора
одновременно означают две копии модели, и система снимет Ollama. После
перезапуска сервис сам возвращает в очередь незаконченные разборы.

## Адреса

Базовый путь: `/api/v1`. Все ответы — JSON в UTF-8 (кроме картинки
страницы). Ошибки — в едином виде:

```json
{ "error": { "code": "not_found", "message": "Разбор с таким ID не найден" } }
```

### `POST /api/v1/parses` — отправить документ

Форма `multipart/form-data`, поле `file`. Форматы: PDF, PNG, JPG. Предел
размера — 25 МБ (`PARSER_MAX_UPLOAD_MB`).

Ответ **202 Accepted** сразу, не дожидаясь разбора; заголовок `Location`
указывает на статус.

```json
{
  "id": "999f2dad975241439cbab7d617a1e786",
  "status": "queued",
  "filename": "receipt.png",
  "size_bytes": 29881,
  "created_at": "2026-09-24T12:49:54+00:00",
  "started_at": null,
  "finished_at": null,
  "queue_position": 1,
  "error": null,
  "summary": null,
  "links": {
    "self": "/api/v1/parses/999f2dad975241439cbab7d617a1e786",
    "result": "/api/v1/parses/999f2dad975241439cbab7d617a1e786/result"
  }
}
```

| Код | Когда |
|-----|-------|
| 400 `file_missing` | нет поля `file` |
| 413 `file_too_large` | файл больше предела |
| 415 `unsupported_format` | не PDF/PNG/JPG (в ответе `allowed`) |

### `GET /api/v1/parses/{id}` — статус (и результат)

Тот же объект, что выше. Когда `status` = `done`, в нём есть поле
`result` — полный результат (формат ниже). Так потребитель опрашивает один
адрес, пока разбор не закончится, и сразу получает данные. Рекомендуемый
интервал опроса — 2 секунды.

При `failed` — поля `error` (причина) и `logs` (журнал шагов до ошибки).

404 `not_found` — разбора нет или ID неверного формата (ID — 32
шестнадцатеричных символа).

### `GET /api/v1/parses/{id}/result` — только результат

Файл `result.json` как есть. 409 `not_ready`, если разбор ещё не готов
(в ответе текущий `status`).

### `GET /api/v1/parses/{id}/pages/{n}/image` — картинка страницы

PNG страницы `n` (с 1). **Координаты полей относятся именно к этой
картинке**, пиксель в пиксель: у PDF это страница в 300 dpi, по которой шло
распознавание; у фото — исходные пиксели без поворота по EXIF.

### `GET /api/v1/parses` — список разборов

Новые сверху, без поля `result` (лёгкий ответ для истории). Параметр
`limit` (по умолчанию 100).

```json
{ "items": [ { "id": "…", "status": "done", "summary": { … }, … } ], "count": 1 }
```

### `DELETE /api/v1/parses/{id}` — удалить разбор

204 — удалён вместе с файлами. 409 `busy` — разбор сейчас обрабатывается.

### `GET /api/v1/health` — проверка

```json
{ "status": "ok", "service": "parser_service", "version": "1.0.0",
  "queue_length": 0, "processing": null,
  "llm": { "url": "http://host.docker.internal:11434", "reachable": true,
           "models": ["mistral:latest", "llama3:latest"] } }
```

`llm.reachable: false` — Ollama не отвечает. Сервис при этом работает:
поля соберут правила по координатам (в результате `extracted_by: "rules"`
и предупреждение в `warnings`).

## Формат результата (schema_version 1.0)

```json
{
  "schema_version": "1.0",
  "id": "999f2dad975241439cbab7d617a1e786",
  "status": "done",
  "source": { "filename": "receipt.png" },
  "engine": {
    "ocr": "Tesseract 5.3.4",
    "llm": "mistral:latest",
    "rules": "2026-09-24c …",
    "parser_service": "1.0.0"
  },
  "coordinate_system": {
    "unit": "px",
    "origin": "top-left",
    "relative_to": "pages[].image_url — картинка страницы, по которой шло распознавание"
  },
  "pages": [
    {
      "number": 1,
      "width": 900,
      "height": 650,
      "image_url": "/api/v1/parses/999f…/pages/1/image",
      "table_grid": null,
      "words": [ { "x": 63, "y": 67, "w": 197, "h": 25, "text": "PRIORBANK", "confidence": 92 } ]
    }
  ],
  "documents": [
    {
      "index": 1,
      "page": 1,
      "document_type": "чек",
      "category": "банковские комиссии",
      "extracted_by": "model",
      "validation": { "valid": true, "errors": [] },
      "fields": [
        {
          "name": "total",
          "label": "Сумма",
          "kind": "standard",
          "value": "258.00",
          "source": "model",
          "boxes": [ { "page": 1, "x": 160, "y": 100, "w": 90, "h": 30,
                       "text": "258.00", "confidence": 93 } ],
          "bbox": { "x": 160, "y": 100, "w": 90, "h": 30 }
        },
        {
          "name": "RRN",
          "label": "RRN",
          "kind": "extra",
          "value": "203899067977",
          "source": "rules",
          "boxes": [ { "page": 1, "x": 157, "y": 407, "w": 255, "h": 25,
                       "text": "203899067977", "confidence": 96 } ],
          "bbox": { "x": 157, "y": 407, "w": 255, "h": 25 }
        }
      ],
      "fields_total": 2,
      "fields_located": 2
    }
  ],
  "summary": { "documents": 1, "fields": 2, "fields_located": 2,
               "document_type": "чек", "category": "банковские комиссии",
               "total": "258.00", "currency": null },
  "warnings": [],
  "logs": [ "НАЧАЛО ОБРАБОТКИ: receipt.png", "…" ],
  "timing": { "created_at": "…", "started_at": "…", "finished_at": "…", "duration_sec": 5.5 }
}
```

### Поля результата

**pages[]** — страницы документа.
- `width`, `height` — размер картинки страницы в пикселях.
- `image_url` — картинка, к которой относятся все координаты.
- `words` — все распознанные слова с координатами (слой OCR целиком).
- `table_grid` — линейки таблицы бланка (`rows` — y, `cols` — x), если
  страница разлинована; иначе `null`.

**documents[]** — извлечённые записи. Обычно одна на страницу; у
многостраничного счёта может быть одна на весь документ.
- `page` — страница, к которой относятся координаты полей записи.
- `extracted_by` — `model` (модель + правила) или `rules` (модель не
  ответила, запись собрана только правилами).
- `validation` — проверки валидатора (дата, валюта, сумма).
- `fields_total` / `fields_located` — сколько полей извлечено и у скольких
  найдено место на странице.

**fields[]** — поля записи: сначала стандартные, затем дополнительные.
- `name` — ключ поля. Для стандартных: `total`, `date`, `company`,
  `invoice_number`, `vat`, `currency`. Для дополнительных — подпись из
  документа («Итого по разделу I (2024)», «RRN»).
- `label` — подпись для человека.
- `kind` — `standard` или `extra`.
- `value` — значение (строка или число, как извлечено).
- `source` — кто поставил значение: `model` или `rules` (правила добавили
  поле или дочитали обрывок модели).
- `boxes` — прямоугольники слов, на которых стоит значение. Каждый
  совпадает с одним распознанным словом страницы: те же `x`, `y`, `w`,
  `h`, `text`. Значение из нескольких слов («1 130») — несколько рамок.
- `bbox` — общий прямоугольник всех `boxes`; `null`, если место не найдено.

**Координаты:** пиксели, начало — левый верхний угол картинки страницы,
`x` вправо, `y` вниз. Чтобы нарисовать рамку поверх картинки, показанной в
другом размере, умножьте на `показанная_ширина / pages[].width` (и так же
по высоте).

**warnings[]** — то, что стоит показать человеку: модель не ответила, у
поля нет места на странице, размер картинки не совпал с распознанным.

### Совместимость

Новые поля в результат могут добавляться без смены версии — потребитель
должен игнорировать незнакомые поля. Удаление или переименование поля,
смена единиц координат — только с новой `schema_version`.

## Пример: потребитель на Python

```python
import time, requests

BASE = "http://localhost:8000/api/v1"

with open("баланс.pdf", "rb") as f:
    parse_id = requests.post(f"{BASE}/parses", files={"file": f}).json()["id"]

while True:
    view = requests.get(f"{BASE}/parses/{parse_id}").json()
    if view["status"] in ("done", "failed"):
        break
    time.sleep(2)

for doc in view["result"]["documents"]:
    for field in doc["fields"]:
        print(field["label"], field["value"], field["bbox"])
```

То же самое из консоли: `python tools/parse_client.py submit баланс.pdf --wait`.
